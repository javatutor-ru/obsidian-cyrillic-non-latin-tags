# Cyrillic and Non-Latin Tags (Плагин для Obsidian)

Плагин динамически добавляет специальные CSS-классы к тегам, содержащим любые нелатинские буквы (кириллицу, иероглифы, диакритические знаки и т. д.), в режиме редактирования (**Editing view**). 

Это позволяет изменять внешний вид нелатинских тегов через CSS или настраивать их оформление с помощью сторонних плагинов (например, *Colored Tags Wrangler*).

## Как это работает для пользователя

Пользователю достаточно установить и активировать плагин в настройках Obsidian. Он не требует никакой конфигурации и управляется одной кнопкой включения/выключения.

Плагин анализирует содержимое тега и обрабатывает только те, в которых есть хотя бы одна нелатинская буква.

**Латинские теги** (например, `#task123`) остаются нетронутыми и сохраняют стандартные классы Obsidian.

**Нелатинские теги** получают два дополнительных класса:
  - **Общий класс:** `cm-tag-non-latin` — для массового изменения стиля всех нелатинских тегов.
  - **Персональный динамический класс:** `cm-tag-[имя_тега]` — для точечной настройки конкретного тега.

**Пример.** Тег `#завершено` получит общий класс `cm-tag-non-latin` и персональный класс `cm-tag-завершено`.



## Примеры стилизации через CSS

Вы можете использовать эти классы в своем CSS-файле из папки `.obsidian/snippets`, чтобы визуально выделить теги.

### Стилизация всех нелатинских тегов

```css
.cm-tag-non-latin { 
 	color: whitesmoke; 
 	background-color: green; 
} 
```

### Стилизация конкретного нелатинского тега

Для тега `#идея1` плагин создаст персональный класс `cm-tag-идея1`:
```css
.cm-tag-идея1 { 
 	background-color: royalblue; 
 	color: #ffffff; 
	font-weight: bold; 
} 
```

### Работа со вложенными тегами. Косая черта

Следуя стилю Obsidian для латинских тегов, плагин удаляет в имени класса косую черту для вложенных нелатинских тегов, таких как `#книга/глава1`.

В структуре DOM имя класса имеет вид: `<span class="cm-tag-книгаглава1">`.

Оформление в CSS-файле:
```css
.cm-tag-книгаглава1 {    
    background-color: darkgoldenrod;
}
```

Этот подход также обеспечивает совместимость со сторонними плагинами для стилизации вложенных нелатинских тегов.

## Детали реализации для разработчиков

Каждый тег в Obsidian формируется из нескольких элементов `<span>`. Когда плагин обнаруживает нелатинский тег, он последовательно обходит все составляющие его HTML-элементы и добавляет в их атрибут `class` дополнительные классы.

HTML-элементы латинских тегов остаются нетронутыми.

### Вложенность элементов \<span\>

Когда к элементу `<span>` добавляется класс, в структуре DOM автоматически формируется дополнительный вложенный элемент `<span>`, куда и попадает содержимое тега.

Получается такая структура:
```html
<span class="..."> <!-- исходный родительский элемент -->
	<span class="...">имя_тега</span> <!-- вложенный элемент -->
</span>
```

Новые классы плагин добавляет только вложенным элементам `<span>`. Родительские элементы сохраняют свои исходные классы Obsidian.


### Использование сторонних плагинов для оформления внешнего вида тегов

Чтобы сторонние плагины имели возможность определять и оформлять нелатинские теги, вложенные элементы `<span>` должны иметь стандартный класс Obsidian `cm-hashtag`, поэтому плагин также добавляет элементам этот класс.

### Вложенность элементов и сохранение стилей
 
Когда появляется вложенная структура элементов, содержащих класс `cm-hashtag`, начинает изменяться стандартное оформление: появляются лишние отступы, уменьшается шрифт тега.

Это происходит при следующем наложении классов:

```html
<span class="cm-hashtag ..."> <!-- родительский элемент -->
	<span class="cm-hashtag ...">имя_тега</span>
</span>
```

Поэтому в плагин интегрировано расширение темы, которое устраняет влияние родительского элемента `<span>` на оформление нелатинских тегов:

```javascript
const tagThemeExtension = EditorView.theme({
    ".cm-hashtag:has(.cm-tag-non-latin)": {
        display: "contents !important",
        fontSize: "inherit !important",
        lineHeight: "inherit !important",
        fontFamily: "inherit !important",
        fontWeight: "inherit !important"
    }
});
```


## Структура DOM

Тег в Obsidian формируется из двух или нескольких элементов `<span>`. Обходя синтаксическое дерево, плагин анализирует узлы, определяет нелатинские теги и дополнительно накладывает на элементы следующие классы.

### Классы для всех элементов \<span\>

* `cm-hashtag` — базовый системный класс Obsidian.
* `cm-tag-non-latin` — общий класс для всех нелатинских тегов.
* `cm-tag-[имя_тега]` — персональный динамический класс. Имя тега формируется «как есть», полностью сохраняя нижние подчеркивания (`_`), косые черты (`/`) и эмодзи.

### Точечные классы для фиксации границ тега
1. Первый элемент (символ `#`) дополнительно получает класс `cm-hashtag-begin`.
2. Последний элемент (конец тега) дополнительно получает класс `cm-hashtag-end`.


### Пример структуры тега #тег\_тест

Obsidian разбивает такой тег с подчеркиванием на три отдельных элемента `<span>`. Плагин находит их в синтаксическом дереве и добавляет им классы:
```html
<!-- 1. Первый элемент (символ решетки '#') -->
<span class="cm-hashtag cm-hashtag-begin cm-tag-non-latin cm-tag-тег_тест">#</span> 

<!-- 2. Второй элемент -->
<span class="cm-hashtag cm-tag-non-latin cm-tag-тег_тест">тег_</span> 

<!-- 3. Последний элемент -->
<span class="cm-hashtag cm-hashtag-end cm-tag-non-latin cm-tag-тег_тест">тест</span> 
```

### Эмодзи

Эмодзи (например, #test😊) **не превращают** тег в нелатинский, если все остальные буквы в нем — латинские.


## Тестирование

Исходный код покрыт модульными тестами с помощью `Vitest`. Проверяются лингвистические комбинации, граничные ASCII-символы, вложенные теги и эмодзи.
